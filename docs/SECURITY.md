# Security and privacy

VALSHOP is an independent companion and uses unofficial Riot client APIs. Riot authentication may change or require periodic reconnection.

## Controls

- Riot passwords are entered only on Riot-controlled pages.
- Riot sessions and permanent companion credentials are stored through Windows Credential Manager/keyring, never the cache database or settings JSON.
- Production backend normally receives only normalized shop data, not Riot tokens.
- Pairing challenges expire, are rate-limited and single-use, and require an unexposed verifier before a permanent credential is released.
- Permanent device credentials are random; only SHA-256 hashes are stored server-side. Revocation is per device.
- Discord webhook secrets and temporary pairing credentials are Fernet-encrypted at rest.
- Snapshot and wishlist inputs are Pydantic-validated; SQLAlchemy parameterizes database operations.
- CORS is configured explicitly through `ALLOWED_ORIGINS`; production rejects empty encryption configuration at startup.
- Rotating desktop logs redact messages involving authorization, tokens, webhooks, and secrets.

## Operational requirements

Use HTTPS for the public site and API. Generate a strong Fernet `ENCRYPTION_KEY`, restrict `ALLOWED_ORIGINS`, protect database and VAPID keys, and never commit `.env`, certificates, or generated secrets. Rotate exposed secrets immediately and revoke affected companion devices.

Unsigned releases can trigger SmartScreen. Production releases should be Authenticode-signed with a real organization certificate; no test certificate is generated by this repository.

Security reports should include the affected version and reproduction steps without live credentials.
